# Token Move 2.0 — หลายกลุ่ม · Loop · Flip

Extension ภาษาไทยสำหรับ GM ใน Owlbear Rodeo เคลื่อน Token หลายตัวเป็นกลุ่ม และสั่งหลายกลุ่มให้เดินคนละเส้นทางพร้อมกันได้

## สิ่งที่เพิ่มในรุ่น 2.0.0

- เพิ่มกลุ่มใหม่จาก Token ที่เลือกได้เรื่อย ๆ แต่ละกลุ่มมีชื่อ จุด A/B ความเร็ว และการตั้งค่าของตัวเอง
- กลุ่มหนึ่งมี Token หนึ่งตัวหรือหลายตัวก็ได้ วัตถุเคลื่อนตาม offset ของเส้นทางที่บันทึกไว้
- เดินเที่ยวเดียว หรือ Loop ไปกลับ A ↔ B ต่อเนื่อง
- Flip รูป Token ตามทิศเดิน เมื่อกลับตัวจะหันหน้าอีกทาง เลือกได้ว่าภาพต้นฉบับหันซ้ายหรือขวา
- เริ่ม/หยุดทีละกลุ่ม หรือเริ่ม/หยุดทุกกลุ่ม เพิ่มกลุ่มใหม่ได้ขณะที่กลุ่มอื่นกำลังเดิน
- หยุดกลางทางแล้วเริ่มต่อได้ รวมถึงตอนกำลังกลับ A
- กลับ A พร้อมคืนขนาดและ Flip ที่บันทึกไว้ หรือลบเฉพาะกลุ่มโดยไม่ลบ Token
- บันทึกกลุ่ม เส้นทาง และการตั้งค่าไว้ใน Scene แยกชุดตามผู้ควบคุม หลังรีโหลดโหลดกลุ่มกลับมาได้ แต่ต้องกดเริ่มใหม่
- ป้องกัน Token ตัวเดียวถูกหลายกลุ่มสั่งเดินพร้อมกัน

## อัปเดตเว็บไซต์เดิมแบบพร้อมใช้

ใช้ `token-move-v2-hosting.zip` สำหรับอัปโหลดไฟล์ที่ build แล้ว ไม่ต้องติดตั้ง Node.js

1. แตก ZIP จะได้โฟลเดอร์ที่มี `index.html`, `background.html`, `manifest.json`, `icon.svg`, `_headers` และ `assets/`
2. เปิดโปรเจกต์เดิมใน Netlify → **Deploys** → เลื่อนหาพื้นที่อัปโหลดแบบลากวาง
3. ลากโฟลเดอร์ที่มีไฟล์ตามข้อ 1 ลงไป แล้วรอ **Published** โฟลเดอร์นี้ต้องมี `index.html` อยู่ข้างในทันที ไม่ซ้อนโฟลเดอร์อีกชั้น
4. เปิด URL เว็บไซต์เดิมต่อท้าย `/manifest.json` ตรวจว่า `version` เป็น `2.0.0`
5. กลับห้อง Owlbear กด **Ctrl + Shift + R** แล้วเปิด Token Move ใหม่ ควรเห็น **Token Move 2** และปุ่ม **เพิ่มกลุ่มจาก Token ที่เลือก**
6. ถ้าแผงยังใช้ขนาดเก่า ให้โหลด Extension จาก manifest ใหม่ผ่านหน้าจัดการ Extensions ของ Owlbear

ZIP ต้องแตกก่อนนำขึ้น Netlify ไม่ใช่ไฟล์ติดตั้งที่อัปโหลดเข้า Owlbear โดยตรง

หาก Netlify เชื่อม GitHub ไว้ การลากวางจะอัปเดตเว็บ แต่ไม่เปลี่ยนซอร์สใน GitHub การ build จาก GitHub ครั้งถัดไปจะใช้ซอร์สใน repository จึงควรอัปเดตซอร์สตามหัวข้อถัดไปด้วย

## อัปเดตผ่าน GitHub

ใช้ `token-move-v2-source.zip` แตกไฟล์ แล้วอัปโหลด **ไฟล์และโฟลเดอร์ข้างในทั้งหมด** ไปที่ระดับบนสุดของ repository เดิม ให้ `package.json` อยู่ระดับบนสุด และคงโครงสร้าง `src/`, `public/`, `tests/` ไว้

1. เปิดหน้า **Code** ของ repository → **Add file** → **Upload files**
2. ลากรายการข้างในโฟลเดอร์ที่แตก ZIP ไปใส่ รวมโฟลเดอร์ `src`, `public`, `tests` ให้เขียนทับไฟล์ชื่อเดิม
3. กด **Commit changes** เข้า branch `main`
4. หาก Netlify เชื่อม repository และ branch นี้ไว้ จะเริ่ม build อัตโนมัติ
5. ตั้ง Build command เป็น `npm run build` และ Publish directory เป็น `dist` ไฟล์ `netlify.toml` ที่ให้มาตั้งค่านี้ไว้แล้ว ใช้ Node.js 22
6. รอ Published แล้วตรวจ manifest และรีโหลด Owlbear ตามขั้นตอนด้านบน

รุ่นนี้เปลี่ยนหลายไฟล์ ต้องอัปเดตทั้งชุด ไม่ใช่เปลี่ยนเพียง `background.ts` หรือ `manifest.json`

## ติดตั้งใหม่

โฮสต์ไฟล์ build ที่ root ของเว็บไซต์ HTTPS เช่น Netlify โดยเก็บ `manifest.json` ระดับเดียวกับ `index.html` รุ่นนี้ใช้ URL `/index.html`, `/background.html`, `/icon.svg` หากใช้โฟลเดอร์ย่อยต้องปรับ manifest ให้ตรงก่อน

เข้า Owlbear Rodeo → Extensions → Add Extension แล้วใส่ `https://ชื่อเว็บไซต์/manifest.json` จากนั้นเปิดใช้งานในห้อง เข้าห้องในฐานะ GM และเปิด Scene

## สร้างหลายกลุ่มและให้เดินพร้อมกัน

1. ใช้เครื่องมือเลือกของ Owlbear เลือก Token หนึ่งตัวหรือหลายตัวที่ปลดล็อกแล้ว
2. เปิด Token Move กด **＋ เพิ่มกลุ่มจาก Token ที่เลือก** ระบบบันทึกตำแหน่งปัจจุบันเป็น A ของกลุ่มใหม่
3. กด **⌖ คลิกเลือก B** แผงจะปิด ให้คลิกปลายทางบนแผนที่ แผงจะเปิดกลับมาและแสดงพิกัด B กด Esc เพื่อยกเลิกได้
4. ตั้งชื่อกลุ่ม ความเร็ว รูปแบบ Loop และ Flip แล้วกด **บันทึกการตั้งค่า**
5. กด **▶ เริ่มกลุ่มนี้**
6. เลือก Token ชุดอื่นบนแผนที่ แล้วกด **＋ เพิ่มกลุ่มจาก Token ที่เลือก** ทำซ้ำเพื่อสร้างกลุ่มถัดไป กลุ่มเดิมยังเดินต่อ
7. คลิกชื่อกลุ่มในรายการด้านบนเพื่อดูและควบคุมกลุ่มนั้น

A และ B อ้างอิงวัตถุตัวแรกของกลุ่ม ดูพิกัด A เพื่อระบุตัวอ้างอิง ตัวอื่นเคลื่อนตาม offset ที่บันทึกไว้ หากอยากให้แต่ละตัวไปคนละปลายทาง ให้แยกคนละกลุ่ม

ปุ่ม **＋** ขนาดเล็กเพิ่มกลุ่มว่างได้ แล้วเลือก Token กด **บันทึก A / เปลี่ยน Token** ปุ่มนี้เปลี่ยนสมาชิกทั้งชุดและล้าง B เดิม ต้องเลือก B ใหม่

## เลือก B จากวัตถุอ้างอิง

วางวัตถุไว้ตรงปลายทาง เลือกเพียงหนึ่งชิ้น แล้วกด **ใช้ตำแหน่งวัตถุที่เลือก 1 ชิ้นเป็น B** ระบบคัดลอกพิกัดขณะกดเท่านั้น วัตถุอ้างอิงไม่ถูกเพิ่มเป็นสมาชิกกลุ่ม และการย้ายหมุดภายหลังไม่เปลี่ยน B จนกว่าจะกดอีกครั้ง

## ตั้ง Loop และ Flip

1. เลือกกลุ่ม หากกำลังเดินให้กด **หยุด** ก่อน
2. เลือก **Loop ไปกลับ A ↔ B** และเปิด **Flip Token ตามทิศเดิน**
3. ตั้ง **ภาพต้นฉบับหันไปทาง** ให้ตรงกับภาพก่อน Flip เช่น รูปม้าต้นฉบับหันขวา ให้เลือก **ขวา →**
4. กด **บันทึกการตั้งค่า** แล้ว **เริ่มกลุ่มนี้**

เส้นทางที่เดินซ้าย/ขวาจะหันตามทิศเดิน เส้นทางแนวตั้งจะสลับ Flip ในเที่ยวกลับ A ขนาดภาพและ scale แนวตั้งคงเดิม ระบบไม่หมุนภาพเพิ่ม

ถ้าหันผิด ให้หยุด เปลี่ยนภาพต้นฉบับเป็นอีกด้าน บันทึก แล้วเริ่มต่อ การตั้งค่านี้ใช้ร่วมทั้งกลุ่ม หากภาพต้นฉบับแต่ละตัวหันคนละด้าน ให้แยกกลุ่ม

Flip ใช้กับวัตถุชนิดรูปภาพ ส่วนรูปทรงและข้อความเคลื่อนที่ได้ แต่ไม่ Flip รูปหันหน้าตรงอาจดูเปลี่ยนทิศไม่ชัด

## ปุ่มควบคุม

| ปุ่ม | การทำงาน |
| --- | --- |
| เริ่มกลุ่มนี้ | เริ่มหรือเดินต่อจากตำแหน่งปัจจุบัน |
| หยุด | หยุดเฉพาะกลุ่มนี้และบันทึกตำแหน่ง/Flip ปัจจุบัน |
| เริ่มทุกกลุ่ม | เริ่มกลุ่มที่มี A/B ครบและยังไม่เดิน กลุ่มที่ Token ซ้ำกับกลุ่มกำลังเดินจะแจ้งข้อผิดพลาด |
| หยุดทุกกลุ่ม | หยุดกลุ่มของตัวควบคุมแท็บนี้ และยกเลิกการเลือก B |
| กลับ A + คืน Flip | หยุดกลุ่ม แล้วย้ายกลับ A พร้อมคืนขนาดและ Flip ตอนบันทึก A |
| ลบกลุ่ม | หยุดและลบเส้นทาง Token ยังอยู่บนแผนที่ |

หลังแก้การตั้งค่า ต้องกดบันทึกก่อนเริ่มเดิน โหมดเที่ยวเดียวเมื่อถึง B ให้กดกลับ A ก่อนเริ่มรอบใหม่

## การบันทึกและขอบเขต

- บันทึกกลุ่มและการตั้งค่าอัตโนมัติลง Scene เมื่อเพิ่ม/แก้/ลบกลุ่มหรือกำหนด A/B ข้อมูลแยกตาม ID ผู้ควบคุม กลุ่มของ GM คนอื่นจะไม่ปรากฏในแผงนี้
- หลังรีโหลดหรือเปิด Scene ใหม่ กลุ่มที่บันทึกจะโหลดกลับมาในสถานะหยุด ต้องกดเริ่มใหม่ ไม่มีระบบย้ายงานไป GM คนอื่น
- อัปเดตจากรุ่น 1 ต้องสร้างกลุ่มใหม่ เพราะรุ่น 1 ไม่ได้บันทึกเส้นทางลง Scene
- ต้องใช้ GM เปิดห้องและ Scene ค้างไว้ ปิดแผงได้ แต่การปิดแท็บ รีโหลด เปลี่ยน Scene เสียสิทธิ์ GM หรือเครื่อง sleep จะหยุด/ขัดจังหวะการเดิน
- ไม่ควรใช้ GM บัญชีเดียวกันเปิดห้องเดียวกันหลายแท็บแล้วสั่ง Token ชุดเดียวกัน การป้องกัน Token ซ้ำครอบคลุมภายในตัวควบคุมแท็บเดียวกัน
- วัตถุต้องปลดล็อก หากมี attachment ให้เลือกตัวหลัก ลูกเคลื่อนตาม attachment ของ Owlbear หากวัตถุถูกลบ ล็อก หรือแนบระหว่างเดิน ระบบหยุดกลุ่มนั้น
- หยุดกลุ่มก่อนลาก ย่อขยาย หมุน หรือแก้ attachment ของ Token ด้วยมือ
- เส้นทางตรง ไม่ค้นหาเส้นทาง ไม่หลบกำแพง ไม่คำนวณกฎเกม และไม่บังคับ snap เข้ากริด
- ความเร็ว 0.1–20 ช่อง/วินาที อ้างอิง DPI ของกริด โหมดค่อย ๆ ออกตัวใช้เวลาเดินทางเท่าเดิม แต่ความเร็วระหว่างทางเปลี่ยนไป
- โปรแกรมไม่ได้ตั้งเพดานจำนวนกลุ่ม จำนวน Token/กลุ่มที่เดินพร้อมกันจริงขึ้นอยู่กับเครื่อง เบราว์เซอร์ เครือข่าย และข้อจำกัด Owlbear

## แก้ปัญหาโหลด Extension

- ตรวจว่า `/manifest.json` แสดง `version: 2.0.0` ไม่ใช่หน้า HTML และ `/index.html` เปิดเห็น Token Move 2
- เปิดเว็บตรง ๆ จะเห็น “ตัวอย่าง” และปุ่มกดไม่ได้ ต้องเปิดผ่าน Owlbear เพื่อสั่ง Token
- เก็บ `_headers` ระดับเดียวกับ `index.html` เพื่อเปิด CORS ใน Netlify
- อย่าเติมจุดท้าย hostname และอย่าเปลี่ยน manifest กลับเป็น `./index.html` รุ่นนี้ใช้ `/index.html`
- ถ้าเลือก B ไม่ได้ ตรวจว่าเป็น GM เปิด Scene บันทึก A แล้ว และหยุดกลุ่มนั้นก่อน รุ่นนี้เปิด tool ก่อนเลือก mode แล้ว
- ถ้ายังเห็นหน้าเก่า ตรวจ Published deploy แล้วกด Ctrl + Shift + R หากจำเป็นโหลด Extension จาก manifest ใหม่

## พัฒนาจากซอร์ส

ใช้ Node.js 22.12 ขึ้นไป:

```sh
npm ci
npm test
npm run build
```

`npm run dev` เปิดเซิร์ฟเวอร์พัฒนา ส่วน `npm run build` ตรวจ TypeScript แล้วสร้างเว็บใน `dist/` เว็บ build แล้วไม่ต้องใช้ Node.js บนโฮสต์

## การตรวจสอบรุ่น 2.0.0

ผ่าน 23 tests และ TypeScript/production build ครอบคลุมหลายกลุ่ม ความเร็วต่างกัน หยุดแยกกลุ่ม ป้องกัน Token ซ้ำ Loop Flip ซ้าย/ขวา/แนวตั้ง หยุดแล้วเริ่มต่อ คืน A/Flip โหลดข้อมูล และแบ่งข้อความสถานะสำหรับหลายร้อยกลุ่ม

ตรวจหน้าควบคุมกับ SDK จริงในห้องจำลองภายในเครื่องแล้ว: เพิ่มสองกลุ่ม คลิก B ตั้งชื่อ/ความเร็ว เดินพร้อมกัน หยุดหนึ่งกลุ่ม และโหลดจาก metadata ได้ ยังไม่ได้ทดสอบรุ่น 2 ในห้อง Owlbear จริงหรือยืนยันหลายเครื่อง ควรลอง Token ทดสอบสองกลุ่มหลังอัปเดต
