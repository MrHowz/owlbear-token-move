# Token Move 2.1.1 — ปรับจังหวะเดิน · ล็อคช่องกริด · LINE ทีละช่อง

Extension ภาษาไทยสำหรับ GM ใน Owlbear Rodeo ควบคุม Token หลายตัว หลายกลุ่ม และหลายเส้นทางพร้อมกัน

## แก้การสะดุดในรุ่น 2.1.1

- แยกจังหวะเดินออกจากคิวคำสั่งและการส่งสถานะแผง เพื่อไม่ให้การรอตอบกลับหยุดทุกกลุ่ม
- เตรียม interaction ใหม่ขณะ interaction เดิมยังเดินอยู่ แทนการหยุดรออ่านข้อมูล บันทึก และเปิดใหม่ทุกประมาณ 20 วินาที
- เริ่มนับเวลาเดินหลังเปิด interaction สำเร็จ ลดการกระโดดตอนเริ่มหลังรอข้อมูล
- เพิ่มความถี่เป้าหมายจากประมาณ 30 เป็น 60 ครั้ง/วินาที และใช้แถวกลุ่ม/รายการ LINE เดิมเมื่ออัปเดตความคืบหน้า
- กลุ่มอื่นยังเดินต่อขณะที่กลุ่มหนึ่งรอบันทึกเมื่อถึง B หยุดหรือเปลี่ยน Scene ยกเลิกงานต่ออายุที่ล้าสมัย

60 ครั้ง/วินาทีเป็นเป้าหมายของตัวควบคุม ไม่ใช่การรับประกันเฟรมเรตหรือความถี่ส่งเครือข่ายจริง Owlbear เป็นผู้จัดการการแสดงผลและซิงก์ หากแท็บถูกพัก เครื่องทำงานหนัก หรือเครือข่ายช้า ยังอาจสะดุดได้

## ความสามารถในรุ่น 2.1

- เลือก B เป็นกึ่งกลางช่องกริดของฉาก คลิกส่วนไหนในช่องก็ได้ ไม่ล็อคตามพิกัดเมาส์ดิบ
- โหมด **LINE** คลิกเลือกช่องเดินทีละช่องตามลำดับ แล้วให้ Token เดินผ่านทุกจุด
- เส้นและวงกลมสีเขียวแสดงช่องที่เลือก เฉพาะผู้ควบคุมและกลุ่มที่กำลังเลือกในแผง
- Enter บันทึก LINE, Backspace ย้อนจุดล่าสุด, Esc ยกเลิก โดยเส้นทางเดิมยังอยู่จนกดบันทึก
- Loop เดินย้อนผ่าน LINE เดิมครบทุกจุด ไม่ตัดตรงจาก B กลับ A พร้อม Flip ตามทิศเดินในแต่ละช่วง
- โหลดกลุ่มรุ่น 2.0 เดิมได้ และปรับ B เดิมเข้ากึ่งกลางช่องอัตโนมัติครั้งแรก หาก B กลายเป็นจุดเดียวกับ A จะให้เลือก B ใหม่ โดยยังเก็บสมาชิกและ A

## วิธีเลือก B ให้ตรงช่อง

1. วาง Token ให้ตรงช่องกริดแล้วเลือก Token หนึ่งตัวหรือหลายตัว
2. เปิดแผง กด **เพิ่มกลุ่มจาก Token ที่เลือก** หรือเลือกกลุ่มเดิมที่หยุดแล้ว
3. กด **เลือกช่อง B** แผงจะปิดลง
4. คลิกช่องปลายทางบนแผนที่ ระบบเลือกกึ่งกลางช่องและเปิดแผงกลับมา
5. ตั้งความเร็ว/Loop/Flip กดบันทึกการตั้งค่า แล้วเริ่มกลุ่มนี้

ปุ่ม **ใช้ช่องของวัตถุที่เลือก 1 ชิ้นเป็น B** จะเลือกกึ่งกลางช่องของวัตถุอ้างอิงเช่นเดียวกัน วัตถุอ้างอิงไม่ถูกเพิ่มเข้าเป็นสมาชิกกลุ่ม และไม่ผูก B ให้ตามวัตถุนั้นเมื่อถูกย้ายภายหลัง

B คือจุดอ้างอิงของ Token ตัวแรกของกลุ่ม ตัวอื่นรักษาระยะห่างตามที่บันทึกไว้ ระบบไม่เปลี่ยนขนาดภาพให้เหลือหนึ่งช่อง วัตถุขนาดใหญ่ยังมีขนาดเดิม เพื่อให้หลายตัวลงช่องตรงกัน ควรวางทุกตัวให้ตรงกริดก่อนบันทึก A

ใช้การ snap ของ Owlbear โดยตรงตามกริดปัจจุบัน ไม่ขึ้นกับการเปิด/ซ่อนเส้นกริดหรือค่าความไวการ snap ของผู้ใช้ บันทึกพิกัดกลางช่องขณะเลือก หากเปลี่ยนขนาด/ชนิดกริดภายหลัง ให้เลือก B หรือ LINE ใหม่

## วิธีสร้าง LINE เลือกช่องเดินเอง

1. เลือกกลุ่มที่บันทึก A แล้ว หากกำลังเดินให้หยุดกลุ่มนี้ก่อน
2. กด **＋ LINE · คลิกเลือกช่องเดินทีละช่อง**
3. คลิกช่องถัดไปบนแผนที่ตามลำดับ เช่น A → ช่องขวา → ช่องขวา → ช่องบน → ช่องบน
4. จะเห็นเส้นสีเขียวเชื่อมช่องที่เลือกและวงกลมที่กึ่งกลางช่อง
5. กด **Enter** ขณะอยู่บนแผนที่ เพื่อบันทึก LINE แผงจะเปิดกลับมา และ B เป็นช่องสุดท้าย
6. เลือกโหมดเที่ยวเดียวหรือ Loop ไปกลับ เปิด Flip ตามต้องการ กด **บันทึกการตั้งค่า → เริ่มกลุ่มนี้**

คีย์ระหว่างเลือกช่อง:

| ปุ่ม | ผล |
| --- | --- |
| Enter | บันทึก LINE ที่เลือก |
| Backspace | ลบจุดล่าสุด แล้วย้อนเส้นกลับหนึ่งจุด |
| Esc | ยกเลิกฉบับร่างและกลับไปเส้นทางเดิม |

สามารถเปิดแผงขึ้นมาแล้วใช้ปุ่ม **บันทึก LINE / ย้อน 1 จุด / ยกเลิก** ได้เช่นกัน ปุ่ม **ซ่อนเส้นทาง** ซ่อนเฉพาะภาพเส้นช่วยดู ไม่ลบเส้นทาง และปุ่ม **ลำดับจุดเดิน** ใช้ดูพิกัดแต่ละช่อง

LINE เชื่อมระหว่างช่องตามลำดับที่คุณคลิก หากต้องการกำหนดทุกช่อง ให้คลิกช่องที่ติดกันทีละช่อง หากคลิกข้ามหลายช่อง Token จะเดินเป็นเส้นตรงเชื่อมระหว่างสองจุดนั้น ไม่มีระบบหลบกำแพงหรือเลือกทางให้อัตโนมัติ รองรับสูงสุด 500 จุดต่อ LINE

สร้าง LINE ใหม่โดยกดปุ่ม LINE อีกครั้งขณะหยุด เส้นเดิมจะถูกแทนที่เมื่อบันทึกเท่านั้น หากกลับไปกด **เลือกช่อง B** จะเปลี่ยนกลุ่มนั้นกลับเป็นเส้นตรง A → B

## Loop และ Flip

- โหมด **เที่ยวเดียว → B** เดินผ่านช่องที่เลือกจนถึง B แล้วหยุด
- โหมด **Loop ไปกลับ A ↔ B** เดินครบ LINE ไป B แล้วผ่านจุดเดิมย้อนกลับ A วนต่อเนื่อง
- Flip ใช้กับรูปภาพ Token ตามการเดินซ้าย/ขวา เส้นช่วงแนวตั้งจะใช้การสลับ Flip ในเที่ยวกลับ ระบบไม่หมุนภาพเพิ่ม
- ตั้ง **ภาพต้นฉบับหันไปทาง** ให้ตรงกับภาพก่อน Flip ถ้าหันผิด ให้หยุด สลับซ้าย/ขวา บันทึก แล้วเริ่มต่อ
- การตั้งค่านี้ใช้ร่วมทั้งกลุ่ม ถ้าภาพแต่ละตัวหันคนละด้าน ควรแยกกลุ่ม

## หลายกลุ่ม

เลือก Token ชุดอื่นแล้วกด **เพิ่มกลุ่มจาก Token ที่เลือก** ได้เรื่อย ๆ แม้กลุ่มเดิมยังเดินอยู่ แต่ละกลุ่มมีชื่อ ความเร็ว A/B หรือ LINE และการตั้งค่าของตนเอง คลิกชื่อกลุ่มเพื่อเลือกควบคุม

| ปุ่ม | การทำงาน |
| --- | --- |
| บันทึก A / เปลี่ยน Token | เปลี่ยนสมาชิกทั้งชุด บันทึกตำแหน่งปัจจุบันเป็น A และล้าง B/LINE เดิม |
| เริ่มกลุ่มนี้ | เริ่มหรือเดินต่อจากช่วงเส้นทางที่หยุดไว้ |
| หยุด | หยุดเฉพาะกลุ่มนี้ บันทึกตำแหน่งและ Flip ปัจจุบัน |
| เริ่มทุกกลุ่ม | เริ่มกลุ่มที่มีเส้นทางครบและยังไม่เดิน |
| หยุดทุกกลุ่ม | หยุดกลุ่มของตัวควบคุมแท็บนี้ และยกเลิกการเลือกช่อง |
| กลับ A + คืน Flip | หยุด ย้ายกลับ A และคืนขนาด/Flip ตอนบันทึก A |
| ลบกลุ่ม | หยุดและลบเส้นทาง Token บนแผนที่ยังอยู่ |

กลุ่มที่ใช้ Token ซ้ำกับกลุ่มที่กำลังเดินจะเริ่มพร้อมกันไม่ได้ ส่วนกลุ่มอื่นยังทำงานต่อ ไม่มีเพดานจำนวนกลุ่มที่กำหนดในโปรแกรม แต่ความสามารถในการเดินพร้อมกันขึ้นกับเครื่อง เครือข่าย เบราว์เซอร์ และ Owlbear

## บันทึกข้อมูลและข้อจำกัด

- เส้นทาง สมาชิก และการตั้งค่าบันทึกใน Scene แยกตาม ID ผู้ควบคุม หลังรีโหลดโหลดกลุ่มกลับมาในสถานะหยุด ต้องกดเริ่มใหม่
- อัปเดตจาก 2.0 ได้โดยไม่ต้องสร้างกลุ่มใหม่ จุด B เดิมจะถูกปรับเข้ากลางช่อง และ Token จะยังไม่เคลื่อนจนคุณกดเริ่ม รุ่น 1 ไม่ได้เก็บข้อมูลกลุ่มลง Scene
- ต้องเป็น GM และเปิด Scene เปิดแท็บห้องค้างไว้ขณะเดิน ปิดแผงได้ แต่รีโหลด ปิดแท็บ เปลี่ยน Scene เสียสิทธิ์ GM หรือเครื่อง sleep จะขัดจังหวะการเดิน
- ไม่ควรใช้ GM บัญชีเดียวกันสั่ง Token ชุดเดียวกันจากหลายแท็บหรือหลายเครื่อง การป้องกัน Token ซ้ำครอบคลุมภายในตัวควบคุมแท็บเดียวกัน
- เลือกวัตถุหลักที่ปลดล็อก ลูกที่แนบจะตาม attachment ของ Owlbear หากตัวหลักถูกลบ ล็อก หรือแนบระหว่างเดิน ระบบหยุดกลุ่มนั้น
- หยุดกลุ่มก่อนลาก ย่อขยาย หมุน หรือแก้ attachment ด้วยมือ
- ความเร็ว 0.1–20 ช่อง/วินาที อ้างอิง DPI ของกริด โหมดค่อย ๆ ออกตัวใช้เวลาเดินทางเท่าเดิมแต่ความเร็วระหว่างช่วงเปลี่ยนไป
- โปรแกรมไม่ตรวจสิ่งกีดขวาง การวางทางผ่านกำแพงหรือวัตถุอื่นจะไม่หยุด Token อัตโนมัติ

## อัปเดตผ่าน GitHub เดิม

1. แตก `token-move-v2.1.1-source.zip`
2. เปิด repository เดิม หน้า Code → **Add file → Upload files**
3. ลากไฟล์และโฟลเดอร์ข้างในทั้งหมดไปอัปโหลด รวม `src`, `public`, `tests` โดย `package.json` ต้องอยู่ระดับบนสุด รวม 22 ไฟล์
4. Commit เข้า `main` หาก Netlify เชื่อม repository/branch นี้ จะ build อัตโนมัติ
5. รอ Netlify **Published** แล้วตรวจ `/manifest.json` ว่า version เป็น **2.1.1**
6. หยุด Token ในห้องก่อน แล้วกด **Ctrl + Shift + R** เปิดแผง ควรเห็น **Token Move 2.1.1** กลุ่มเดิมจะโหลดกลับมาในสถานะหยุด กดเริ่มเมื่อพร้อม

ไฟล์ `netlify.toml` ตั้ง Build command เป็น `npm run build`, Publish directory เป็น `dist`, Node.js 22 ไว้แล้ว ต้องอัปเดตทั้งชุดเพราะเปลี่ยนหลายไฟล์

## อัปโหลด Netlify แบบพร้อมโฮสต์

ใช้ `token-move-v2.1.1-hosting.zip` แตกไฟล์ แล้วลากโฟลเดอร์ที่ข้างในมี `index.html`, `background.html`, `manifest.json`, `icon.svg`, `_headers`, `assets/` ลงช่องอัปโหลดหน้า **Deploys** ของโปรเจกต์เดิม รอ Published แล้วตรวจ version/รีโหลดตามด้านบน

โฟลเดอร์ต้องมี `index.html` อยู่ข้างในทันที ไม่ซ้อนอีกชั้น การลากไฟล์ขึ้น Netlify จะไม่อัปเดต GitHub หากเชื่อม GitHub อยู่ ควรอัปเดตซอร์สด้วยเพื่อให้ deploy ครั้งถัดไปใช้รุ่นใหม่

## ติดตั้งใหม่และแก้ปัญหาโหลด

โฮสต์ไฟล์ build ที่ root ของเว็บไซต์ HTTPS แล้วเข้า Owlbear Extensions → Add Extension ใส่ `https://ชื่อเว็บไซต์/manifest.json` และเปิดใช้งานในห้อง รุ่นนี้ใช้ `/index.html`, `/background.html`, `/icon.svg` หากโฮสต์ใต้โฟลเดอร์ย่อยต้องปรับเส้นทาง manifest ก่อน

เก็บ `_headers` ไว้ระดับเดียวกับ `index.html` เพื่อเปิด CORS ใน Netlify ตรวจว่า manifest เป็น JSON version 2.1.1 หากเปิดเว็บตรง ๆ จะเห็นตัวอย่างและปุ่มกดไม่ได้ ต้องใช้งานผ่าน Owlbear อย่าเติมจุดท้าย hostname

## พัฒนาจากซอร์ส

ใช้ Node.js 22.12 ขึ้นไป:

```sh
npm ci
npm test
npm run build
```

`npm run dev` เปิดเซิร์ฟเวอร์พัฒนา ส่วน build ตรวจ TypeScript แล้วสร้างเว็บใน `dist/` เว็บที่ build แล้วไม่ต้องใช้ Node.js บนโฮสต์

## การทดสอบ

ผ่าน 39 tests, TypeScript และ production build ครอบคลุมหลายกลุ่ม Loop/Flip LINE หลายมุม รวมถึงจำลองการอ่านข้อมูล บันทึก และต่ออายุที่ตอบกลับช้า การหยุดระหว่างต่ออายุ การเปิดรอบใหม่ก่อนคำตอบเก่ากลับมา การส่งสถานะตามลำดับ และกลุ่มอื่นยังเดินต่อขณะกลุ่มหนึ่งรอบันทึกสุดท้าย

รุ่น 2.1 เคยตรวจหน้าควบคุมกับ SDK ในห้องจำลองภายในเครื่อง ทั้ง snap, LINE, Loop และโหลดข้อมูลใหม่ รุ่น 2.1.1 ยังต้องอัปโหลดและลองในห้อง Owlbear จริงเพื่อยืนยันผลการแสดงผลและการซิงก์หลายเครื่อง ชุดทดสอบไม่ใช่การวัดเฟรมเรตของห้องจริง
